# Поисковый плейбук

## Язык запросов

Определи основной язык источника и ищи на нём: у портала ЕБРД английский, у kursiv.kz русский. В общем веб-поиске запускай одну и ту же идею на двух языках, потому что русская и английская выдачи пересекаются слабо.

**Русские паттерны:** «объявлен тендер», «внедрение ERP», «разработка информационной системы», «цифровая трансформация», «стратегия цифровизации», «платформа данных», «хранилище данных», «внедряет искусственный интеллект», «миграция в облако», «аудит информационной безопасности», «технологический аудит», «подписан меморандум», «планирует IPO», «привлекает инвестиции», «государственная программа цифровизации», «модернизация», «строительство завода», «распределительный центр».

**Английские паттерны:** "ERP implementation", "digital transformation", "data platform", "data governance", "AI solution", "IT due diligence", "cloud migration", "system integrator tender", "request for proposals", "request for expressions of interest", "invitation for bids", "procurement notice", "consulting services", "investment agreement", "IPO", "feasibility study", "project summary document".

**Национальные языки — для разведки** (часть анонсов выходит только на них; результат переводи и цитируй оригинал):
- казахский: «цифрландыру», «ақпараттық жүйе», «енгізу», «жасанды интеллект», «тендер», «инвестиция»;
- азербайджанский: «rəqəmsal transformasiya», «informasiya sistemi», «tətbiq», «süni intellekt», «tender», «investisiya»;
- узбекский (латиница): «raqamlashtirish», «axborot tizimi», «joriy etish», «sun'iy intellekt», «tender», «investitsiya».

Если национальная выдача пустая или нерелевантная, это тоже результат: запиши его в журнал с `results_total`.

Дополнительные паттерны и ключевые слова оператора лежат в `config/settings.json` → `patterns`, `keywords`.

## Как строить запрос

- Один запрос — одна идея: паттерн + ключевое слово + страна (+ сектор). Для свежести добавляй год или месяц («2026», «октябрь 2026»).
- Для порталов используй `site:` (например, `site:ecepp.ebrd.com Kazakhstan`), если выдача это поддерживает.
- Для каждого запроса записывай `pattern` и `keyword` — по ним считается статистика. Формулировки должны быть стабильными между сканами, иначе статистика размывается.
- Для каждого кандидата, который может стать WARM или выше, открывай первоисточник (WebFetch), а не опирайся на сниппет выдачи.

## Уровни источников

- **Tier 1 (первичные):** порталы госзакупок, страницы доноров и ИФИ, раскрытия компаний и бирж (годовые отчёты, ИТ-стратегии, проспекты эмиссии), сайты регуляторов, официальные пресс-релизы компаний и вендоров.
- **Tier 2:** деловые и отраслевые СМИ.
- **Tier 3:** агрегаторы, соцсети, Telegram, вакансии. Это наводка: без подтверждения Tier 1/2 лид не может стать HOT.

**Стартовый список.** Если источник недоступен, отметь это в «Пробелах». Дополнения оператора лежат в `settings.json` → `sources_extra`.
- KZ: kursiv.kz, forbes.kz, inbusiness.kz, capital.kz, goszakup.gov.kz, kase.kz, aix.kz, stat.gov.kz
- AZ: trend.az, report.az, apa.az, interfax.az, etender.gov.az, bse.az, azpromo.az, stat.gov.az
- UZ: gazeta.uz, kun.uz, daryo.uz, uzdaily.uz, xarid.uz, uzse.uz, stat.uz
- Международные: ecepp.ebrd.com, Project Summary Documents на ebrd.com, projects.worldbank.org, adb.org, disclosures.ifc.org

## Объём и распределение

Значения берутся из `config/settings.json` → `params`.

На каждую страну приходится минимум `min_queries_per_country` (10) запросов:
- `cross_queries_per_country` (4) кросс-отраслевых, по одному на линии [AI], [DG], [IS], [DD]/[RM]. Сектор у них — «кросс»;
- остальные — отраслевые (сектор × триггер). Сначала идут сектора из `priority_sectors`, затем по очереди из `sector_order` в выводе `start` (давно не проверенные — первыми). Так за два скана каждый сектор получает хотя бы один запрос в каждой стране.

Состав запросов (подсказки даёт `start`):
1. **Обязательные** (`mandatory`): `adj_score ≥ 60` при 2+ прогонах. Используются всегда, но не больше 60% запросов страны.
2. **Разведка** (`explore`): не меньше 20% запросов скана (с округлением вверх). Это новые комбинации, запросы на национальных языках и комбинации из списка `stale` (не запускались 8+ недель).
3. **Редкие** (`rare`): `adj_score ≤ 25` при 3+ прогонах. Только из списка `rare_eligible`, то есть не чаще раза в 5 сканов.
4. **Равномерные** (`uniform`): всё остальное.
5. **Watchlist** (`watchlist`): по одному запросу на компанию из `watchlist` с неистёкшим сроком. В минимум не входят и в статистике не учитываются.

Для страны, где больше всего пустых запросов, добавь 1–2 запроса сверх плана, но не больше `max_queries_per_country`.

## Как считается статистика (делает скрипт)

- **Run-score запроса** — средний score до 3 лучших лидов со статусом NEW или UPDATE, которые этот запрос нашёл первым. Если релевантных лидов нет, run-score = 0, но прогон засчитывается.
- Технические ошибки (`tech_error: true`) и запросы watchlist в статистику не идут.
- `avg_score` = (старое среднее × прогоны + run-score) / (прогоны + 1).
- `adj_score` = `avg_score` × (0,5 + f), где f = (подтверждённые + 1) / (подтверждённые + нерелевантные + 2) по отметкам команды. Без отметок `adj_score` = `avg_score`. Все правила распределения используют `adj_score`.

## Когда остановиться

Скан готов, когда:
- выполнены минимумы запросов по всем странам из области скана;
- каждый кандидат уровня WARM и выше прочитан в первоисточнике;
- непокрытые сектора и триггеры перечислены в «Пробелах».

Не останавливайся после первых находок. И не раздувай скан сверх `max_queries_per_country`: качество проверки важнее числа запросов.
